## 1 · WHAT THE BUSINESS IS

**Crew-first travel eSIM.** The eSIM is the *wedge*, not the product.

- **Product name (app):** **Kiki eSIM** (renamed 2026-08-31 from SpicyKiwi). Consumer brand for the wider market is still **NOT LOCKED** — shortlist is **SORU · ROMU · DRIFTO** (all verified clear 2026-05-24 across USPTO Class 9+38, .com, @insta, @tiktok, App Store). Dead names, never reconsider: Peanut, CrewLink, Starnet, Vision.
- **Legal entity:** **Spicy Kiwi, LLC** (Delaware, single-member).
- **Target user:** Emirates cabin crew + pilots → then Etihad → JAL → ANA. Closed/gated community, not open consumer.
- **The wedge:** crew uploads their monthly **Crew Pulse roster screenshot** → on-device OCR parses it into real trips → app pre-builds the right data plan for the countries they'll actually be in. No competitor does this.
- **The moat:** the crew layer on top — layover intel, crew picks/recs, layover hotels, days-abroad + savings tracking, year-in-review.
- **Model:** ONE lifetime crew SIM (one ICCID), many packages loaded onto it. Never one-eSIM-per-trip.
- **JV split:** Balraj = system / tech / ops / legal / finance. Akito = marketing / brand / plan design / face of company. 50/50 by Founders' Agreement (**NOT YET SIGNED** — see §9).
- **Direct competitor:** **Crew SIM** (eSIM Mobile GmbH, Germany, pilot-founder, ~5K users, 41-country map, email-only support, ~$1.50/GB pay-per-MB, no expiry). Price-undercutting was killed as a wedge because of them.

### Commercial model as built into the app (PLACEHOLDER until Zetexa production pricing lands)
Source of truth in code: `src/data/esimCatalog.ts` + `src/data/pricing.ts` + `src/data/zetexaCatalog.ts`.

Three customer journeys, all sitting behind one eSIM card:
- **(A) Regular user** — $2 SIM install fee + pay-as-you-go country bundles.
- **(B) Verified crew** (airline email + code) — **FREE** install + **15% off** all PAYG.
- **(C) Crew + roster upload** — **Roster Plan**: list $40, struck to **$26/mo "first 100 customers"**. Skip 2 monthly uploads → price goes to **$34 and never back to $26**. (Deliberate price-raise headroom.)
- Fair use in the roster plan: **2 GB per 36h layover window**.
- **Carryover-as-margin engine:** give 10 GB, crew uses ~6; leftover is pure margin because supply is bought per-GB as consumed. Roll-over exists but with deliberate tap friction.
- 7-tier cabin-class naming locked 2026-05-24: Economy / Roster Bundle / Premium Economy / Business / First / Cockpit / Refuel.
- 6-scenario refund matrix locked (Netflix-style mid-month, fail-on-arrival refund + 1 GB gift, 3×/yr user-error forgiveness).
- **Backdoor gating strategy:** market as "Emirates crew app", gate to ANY verifiable airline-crew email → expands TAM 5–10×.
- **Install method:** Apple **eSIM Universal Link** (iOS 17.4+) → **no Carrier Entitlement application needed.** This removed months of Apple back-and-forth.

### 11.4 Roster OCR reference (for whoever touches the wedge)
Emirates crew use **Crew Pulse** — a monthly calendar grid, Mon–Sun columns, one cell per day.
Cell anatomy: day number top-left; 3-letter airport code at the bottom (NRT, BKK, JED, CGK, PVG, ZRH, CPT, LHR, DAC, CDG, HND, KIX, DXB…); icon = plane (flying), green up-arrow (day off), person (standby); background colour = trip status (light purple = active pairing, white = off, grey = standby, pink/burgundy = special). Connected purple cells = one multi-leg trip.
**Critical logic:** Emirates crew are DXB-based — almost every trip returns to DXB, so **DXB legs need no eSIM**. Only the outstation layover needs data, sized to layover duration: ~2GB/24h, ~5GB/36h, 10GB+ for longer.
Engine output shape: `{month, trips: [{start_date, end_date, destinations, airline}]}`.
Sample screenshots: `01-Product/mockups/roster-sample-{1,2}.jpeg`.
Known cosmetic backlog: trip-block tail days render as code-less "—" flights and inflate the flight count; XX (green-house) days currently map to OFF.
